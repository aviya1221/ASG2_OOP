  11:00  Lessons learned, then questions

Golden rule: demo the requirements, not the code. Every minute should map to
a requirement or a result.

Demo-day checklist (slide 16):
Prepare
- Freeze a tagged release days before
- Rehearse twice, with a timer
- Seed realistic demo data
- Record a backup video
- Have plan B for network and hardware
On the day
- Arrive early; test projector and network
- Enlarge fonts and zoom in
- Say what the audience should notice
- Tie each step to a requirement
- Keep to time; leave room for questions
Avoid
- Last-minute merges or live coding
- Showing every feature
- Debugging in front of the audience
- Hiding known issues: state them
- Reading from slides

FOR OUR PROJECT
Our slot is 10 minutes, so scale the example down. The class itself is the
live scenario: students check in from their own phones.
